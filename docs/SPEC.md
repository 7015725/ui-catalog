# 约束、要求与验收标准

本文是 ui-catalog 的「施工规范」。新增或修改组件、风格、界面模板时，人和 AI Agent 都按这份文档做、按这份文档验。

- **必须**：不满足就不能合入。
- **应当**：默认要做，确有理由可以不做，但要在提交说明里写清原因。
- **建议**：锦上添花。

文档和代码冲突时，以本文为准，并修正代码或修订本文，不允许两者长期不一致。

---

## 1. 项目定位

| 是什么 | 不是什么 |
|---|---|
| 零依赖、免构建的原生 Web Components 组件库 | 不是 React / Vue 组件库，不引入任何框架 |
| 一份画廊：每个组件和模板都有「预览 / AI 提示词 / 设计说明 / 代码」 | 不是设计稿工具，不提供可视化拖拽编辑 |
| 用 CSS 变量（token）切换 22 套风格 × 浅色 / 深色 | 不为单个风格写分支逻辑 |
| 给 AI Agent 用的提示词库：照着提示词能生成同风格界面 | 提示词不是营销文案，不写空话 |

服务对象有三类：一是直接用 CDN 引入组件的开发者，二是复制提示词交给 AI Agent 的使用者，三是在本仓库里继续扩充内容的人或 Agent。

## 2. 硬性约束（全部为「必须」）

### 2.1 零依赖、免构建

1. `src/` 下的代码不得 `import` 任何第三方包，也不得通过 `<script src>` 加载外部库。
2. 不得引入打包、转译步骤（webpack / vite / babel / TypeScript 编译等）。浏览器直接加载 `src/` 里的 ES Module 就能运行。
3. `package.json` 不得出现 `dependencies`。开发和测试工具（如 playwright）只能临时安装（`npm i --no-save`），不得写进仓库。
4. 页面必须能通过任意静态 HTTP 服务器运行，例如 `node dev-server.mjs` 或 `python3 -m http.server`。

### 2.2 组件实现

1. 组件一律继承 `UIElement`（`src/components/base.js`），用 `register(tag, Class, css)` 注册，并在 `src/components/index.js` 里 import。
2. 标签名必须以 `ui-` 开头，类名为 `UI` + 帕斯卡命名，例如 `ui-split-button` 对应 `UISplitButton`。
3. 对外属性必须声明在 `static props` 里，每个都要有 `default`。复杂数据以 JSON 字符串传入，解析失败时退回默认值，不得抛错导致整块空白。
4. 用户内容必须走 `<slot></slot>`，由基类搬运原始子节点。不得用字符串拼接 `innerHTML` 去替换用户内容。
5. 拼进模板的属性值和外部文本必须经过 `esc()` 转义（见 `more-form.js`），防止 XSS。
6. 重渲染之后要重新查询 DOM 节点再操作，不得持有旧节点（尤其是 `focus()`）。
7. 自定义事件用 `CustomEvent`，事件名小写、不带前缀，数据放在 `detail` 里。对外事件必须带 `bubbles: true`，方便外层委托监听（`Layer` 浮层内部使用的 `open` / `close` 不对外，不受此限）。`on<事件名>` 内联写法由基类支持，不得另造一套。
8. 组件移除时（`disconnectedCallback`）必须清理：定时器、`requestAnimationFrame`、`ResizeObserver` / `MutationObserver` / `IntersectionObserver`、挂到 `body` 的浮层、全局监听。

### 2.3 样式与换肤

1. 组件 CSS、模板 CSS 中的颜色、圆角、阴影、字体、间距、控件高度、动效曲线，只能使用 `var(--ui-*)`。当前 token 包括：
   `--ui-bg --ui-panel --ui-panel-2 --ui-text --ui-sub --ui-line --ui-brand --ui-brand-soft --ui-brand-ink --ui-accent --ui-ok(-soft) --ui-warn(-soft) --ui-danger(-soft) --ui-on-color --ui-button-radius --ui-default-button-text --ui-default-button-bg --ui-default-button-shadow --ui-button-prefix --ui-primary-button-shadow --ui-primary-button-text-shadow --ui-ring --ui-radius(-sm/-lg/-pill) --ui-border-w --ui-shadow(-sm) --ui-blur --ui-font --ui-mono --ui-gap --ui-ctl-h --ui-ease --ui-spring --ui-motion`。新增共享刻度：`--ui-space-* --ui-size-* --ui-font-size-* --ui-font-weight-* --ui-letter-spacing-* --ui-line-height-*`（定义在 tokens.css 的共享刻度区，所有风格与明暗组合均有确定的继承值）。
2. 不得写死十六进制色、`rgb()` 或命名色。只有以下情况例外：
   - `#000` / `#fff` / `transparent`，以及纯黑、纯白带透明度的 `rgba(0,0,0,a)` / `rgba(255,255,255,a)`：用作 `mask`、`color-mix()` 的明暗调节量、阴影、高光、遮罩；
   - 拟物、场景、媒体叠层类组件表现**材质本身的颜色**（金币、灯泡、钢琴黑白键、夜空、天气卡天空、图片上的白色拖柄）。这类组件必须登记在 `src/test/cases.js` 的 `MATERIAL_TAGS` 白名单里并写明理由，回归测试会拦下名单外的写死颜色；
   - 让用户选择颜色的组件（如 `ui-color` 的预设色板）里的预设值，属于数据，不属于样式。
   需要第二种品牌色做渐变、装饰色块时，用辅助色 `--ui-accent`，不得写死粉色、紫色等。
3. 风格差异只能写进 `src/styles/tokens.css`：每套风格提供浅色、深色两份变量，确实表达不了的形态差异写在文件末尾的「风格微调」区，并用 `[data-style="…"]` 限定作用域。组件 JS 里不得判断当前风格。
4. Canvas 绘制的界面不能使用 CSS 变量时，必须用 `getComputedStyle` 读取 `--ui-*` 的值，并在 `data-style` / `data-theme` 变化时重新读取、重画（参照 `canvas-ui.js`）。
5. 新增 token 时，22 套风格 × 浅色 / 深色每个组合都必须有确定的值（可以继承 `:root` 或同风格浅色的值），并同步更新本节第 1 条的清单。涉及文字的 token 要补对比度测试。

### 2.4 自适应

1. 组件按**容器宽度**自适应（`@container`），不得只依赖视口 `@media`。组件放进侧栏、卡片、弹窗里也要正确响应。
2. 任何组件、模板在 320px 宽的容器里都不得产生横向滚动条；确需横向滚动的内容（宽表格、热力图），滚动只能发生在组件内部。
3. 触摸设备上可点击区域应当不小于 36 × 36 px。

### 2.5 无障碍（WCAG 2.1 AA）

1. 文字对比度：正文、次要文字、品牌色文字、语义色文字对其背景均 ≥ 4.5:1，在 22 套风格 × 浅色 / 深色下都要成立。
2. 所有交互都必须能只用键盘完成。复合控件按 WAI-ARIA 模式实现：菜单、标签页、树、网格采用 roving tabindex，`Esc` 关闭浮层并把焦点还给触发器。
3. 焦点必须可见：`:focus-visible` 要有清晰的描边，不得用 `outline:none` 去掉而不补替代样式。
4. 只用图标的按钮必须有可访问名称（`aria-label` 或视觉隐藏文本）；可访问名称要包含按钮上的可见文字。
5. 同一页面里出现多个同类地标时（`nav`、`search`），必须用 `label` 属性区分名称。
6. 装饰性内容（emoji、重复的滚动副本、装饰 SVG）设为 `aria-hidden="true"`。逐字动画、数字滚动等效果要把完整文本放进视觉隐藏节点。
7. 状态变化（加入购物车、派单完成、游戏得分）通过 `aria-live` 或 `role=status` 播报。
8. Canvas 界面必须满足：画布可聚焦，`role="application"` 并带说明；所有操作都有键盘方式；状态变化写进 `aria-live` 区域。

### 2.6 动效

1. 系统开启「减少动态效果」，或页面 `<html data-motion="reduce">` 时，CSS 动画直接到终态，JS 动画直接给出最终结果。加载类动画例外，改为缓慢呼吸。判断统一用 `src/lib/motion.js` 的 `reduced()`。
2. `requestAnimationFrame` 循环必须使用 `loop()`，离开视口或标签页隐藏时自动暂停，组件移除时停止。
3. 动效只做装饰，不得改变语义，也不得成为完成任务的唯一途径。手势操作（刮、拖、长按、画）都要有按钮或键盘替代。

### 2.7 浏览器支持

依据代码实际用到的 `color-mix()`、容器查询、`:where()`，最低支持版本为：Chrome / Edge 111+、Safari 16.2+、Firefox 113+。不得使用比这更新的特性；确需使用时，必须提供降级，并更新本条。

## 3. 各类内容的要求

### 3.1 组件元数据（`src/data/catalog*.js`）

每个组件一条记录，必须包含：

| 字段 | 要求 |
|---|---|
| `id` | 全库唯一，短横线命名 |
| `tag` | 与注册的标签名一致 |
| `name` | 中文名 |
| `cat` | 已有分类之一：表单 / 展示 / 图表 / 导航 / 反馈 / 浮层 / 动效 / 视觉 / 趣味 |
| `brief` | 一句话说明，不超过 40 字 |
| `demo` | 可直接运行的 HTML，演示主要用法和至少一种状态变化 |
| `ai` | 五段式提示词，见 3.4 |
| `design` | `purpose` 为什么存在 / `when` 什么时候用 / `avoid` 什么时候别用，可选 `tips` |
| `wide` | 可选。演示需要宽版时设为 `true`，占两列 |

### 3.2 UI 风格

1. 在 `tokens.css` 里加浅色、深色两条规则，并为 2.3 中的全部 token 赋值。其中 `--ui-accent` 必须显式给出与本风格协调的值，不得继承默认洋红（回归测试会检查）。
2. 在 `src/data/styles.js` 里加一条元信息（名称、特征、代表色），在 `src/data/style-guides.js` 里加该风格的 AI 提示词和设计说明。
3. 风格名必须与已有风格区分得开，不得只是换一种主色。

### 3.3 界面模板（`src/data/templates-*.js`）

每个模板必须包含 `id / name / cat / frame / brief / uses / html / css / init / ai / design`，Web 模板还要有 `url`，Canvas 模板设 `fit: true`。

| 规则 | 要求 |
|---|---|
| 根节点 | `<div class="t-screen t-<id>">` |
| 样式作用域 | `css` 中的选择器都以 `.t-<id>` 开头，只用 `var(--ui-*)`，不得出现十六进制色 |
| 组件优先 | 能用组件库实现的部分不得手写；`uses` 列出实际用到的全部组件标签 |
| 操作逻辑 | `init(root)` 只操作 `root` 内部的节点，不得读写 `document` 的全局状态，可以重复挂载 |
| 移动 APP | 375 宽；内容区 `.t-scr` 独立滚动，带 `role="region"` 和 `aria-label`；有底部导航时传 `label` |
| 专属推荐风格 | 系统 APP，以及视觉设定无法用全站风格表达的 Web 模板（如液态玻璃后台 → `dusk`），可增加 `style` 元字段作为局部推荐风格；该风格必须按 3.2 正式登记；预览只跟随全站明暗，不重建或丢失交互状态；代码出口必须携带同样的风格与主题上下文 |
| Web 页面 | 用 `@container tpl` 自适应，桌面 / 平板 768 / 手机 390 三种宽度下布局都合理，并且发生了实际变化（如侧栏变抽屉、三栏变列表 → 详情） |
| JS 绘制 | 界面主体画在 `<canvas>` 上；按设备像素比绘制；满足 2.3 第 4 条、2.5 第 8 条、2.6 第 2 条 |
| 占位图 | 用 `ph()` 生成，带 `role="img"` 和说明；不得引用外部图片地址 |

### 3.4 AI 提示词格式

**组件提示词**固定五段，供 Agent 解析：

```
【组件】名称 <ui-xxx>
【用途】解决什么问题
【属性】逐个列出：名称、取值、默认值
【视觉】只描述 token 关系，不写具体色值
【交互】hover / active / focus-visible / 键盘 / 各状态的行为
【约束】编号列出禁止事项
```

**模板提示词**按以下顺序写：页面目标 → 整体结构（从上到下）→ 响应式 → 【操作逻辑】（点了什么、状态怎么变）→ 状态（空、加载、出错）→ 无障碍 → 约束。依赖组件清单由画廊自动附在末尾，不要手写。

提示词要求：

1. 用中文，写成可执行的指令，不写形容词堆砌。
2. 「交互」和「操作逻辑」必须写到「触发 → 结果」这个粒度，例如「点加购：购物车角标 +1，并播报『已加入购物车』」。
3. 提示词描述的行为必须和预览里的实际行为一致。

## 4. 验收标准

### 4.1 自动验收（每次提交必过）

| 项目 | 命令 | 通过标准 |
|---|---|---|
| 语法检查 | `npm run check` | 输出「✓ N 个文件语法检查通过」，退出码为 0 |
| 回归测试 | 先 `npm start`，再 `npm test` | 输出「回归测试：N 通过，0 失败」「✓ 全部通过」；画廊组件数等于 README 徽章上的数字 |
| 系统 APP | `npm run test:mobile` | 专属风格、状态保留、响应式、复制代码与独立运行全部通过 |
| 全风格矩阵 | `npm run test:a11y` | 全部风格 × 明暗 × 360 / 820 / 1440 × 三个视图无 axe 问题、无控制台问题、无页面横向溢出 |
| CI | 推送到 `main` 后的 GitHub Actions `test` 工作流 | 显示绿色 |
| Pages | 推送后的 `pages-build-deployment` | 成功；在线页面能看到新内容 |

当前回归测试共 232 条，组件 179 个，模板 20 个，风格 22 套。1.1.0 基线的 95 条用例全部保留。新增内容时必须同步补测试，测试数量只增不减；删除测试要在提交说明里写明原因。

回归测试至少覆盖：

- 组件：属性渲染、默认值、非法 JSON 兜底、键盘操作、浮层开关与焦点归还。
- 风格：22 × 2 组合的文字对比度断言。
- 动效：减少动效时直接到终态；组件移除后动画循环停止。
- 模板：数据字段齐全、CSS 无十六进制色、`init` 可运行、至少一个关键操作的结果断言。
- Canvas：键盘操作、事件派发、切换风格后重新读取 token。

### 4.2 人工 / 半自动验收矩阵

改动涉及哪类内容，就按对应的行验收。

| 维度 | 检查方法 | 通过标准 |
|---|---|---|
| 风格矩阵 | 22 套风格 × 浅色 / 深色逐一切换 | 无错色、无看不清的文字、无残留的写死颜色 |
| 屏宽 | 360 / 820 / 1440 三种宽度 | 页面无横向溢出；组件不溢出卡片 |
| 键盘 | 只用 Tab / Shift+Tab / 方向键 / Enter / Space / Esc | 能完成全部操作；焦点始终可见；关闭浮层后焦点回到触发器 |
| 读屏 | axe-core 扫描（含 best-practice 规则） | 画廊、风格页、模板页 0 个问题 |
| 减少动效 | 打开系统设置，或点顶栏「✨ 动效」 | 没有持续运动；内容完整可读 |
| 控制台 | 浏览全部分类、操作全部模板 | 0 个报错、0 个警告 |
| 泄漏 | 反复切换分类 / 搜索 20 次 | `body` 子节点数和浮层节点数不增长；页面内无重复 `id` |
| 交互 | 逐个点击预览里的全部控件 | 行为与提示词「交互 / 操作逻辑」描述一致 |
| 代码面板 | 复制代码，放进空白页（引入 tokens.css 和 components/index.js） | 能独立运行，外观、行为与预览一致 |
| 提示词 | 复制提示词，交给 AI Agent 生成 | 生成结果的结构和操作逻辑与预览基本一致 |

## 5. 完成的定义

一项改动只有同时满足下面全部条件，才算完成：

1. 满足第 2 节的全部硬性约束；
2. 满足第 3 节对应内容类型的要求；
3. 第 4.1 节自动验收全部通过；
4. 第 4.2、4.3 节中相关的条目逐项勾完；
5. README 和本文档已同步；
6. 提交说明用中文写清：改了什么、为什么、怎么验的。
